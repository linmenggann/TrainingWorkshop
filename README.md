# 教學訓練計畫主持人工作坊

紫色漸層的活動網頁（CSS、JavaScript 內嵌於 `index.html`，照片背景另由同目錄 JPG 載入），包含報名資料預覽、草稿下載、行事曆下載，以及送往 Google Sheets 的報名流程。
活動內容取自「教學訓練計畫主持人工作坊.docx」，日期維持原文的 2026/01/25。

## 試算表及表頭

目標試算表：[Google Sheets](https://docs.google.com/spreadsheets/d/1LEllNReIM9pXQ6M3Jac7CgOgfJ29gNWz5t9qlcP0D1Y/edit)

- 試算表 ID：`1LEllNReIM9pXQ6M3Jac7CgOgfJ29gNWz5t9qlcP0D1Y`
- 分頁名稱：**工作坊報名資料**（必須完全相同）。`gid=0` 不影響程式，接收端依名稱選擇分頁。
- 欄位順序為 A 到 J。可直接複製下面一行，貼到分頁的 **A1**（欄位之間為 Tab）；也可使用 [apps-script/headers.tsv](apps-script/headers.tsv)。

```text
送出時間	姓名	機構名	職稱	負責的職類	目前是否擔任教學訓練計畫主持人	預計參與方式	Email	聯繫電話	報名編號
```

| 欄 | 表頭 | 內容 |
| --- | --- | --- |
| A | 送出時間 | 伺服器產生，台北時間 `yyyy/MM/dd HH:mm:ss` |
| B | 姓名 | 表單 `name` |
| C | 機構名 | 表單 `organization` |
| D | 職稱 | 表單 `job` |
| E | 負責的職類 | 表單 `profession`，12 個選項之一 |
| F | 目前是否擔任教學訓練計畫主持人 | 表單 `host`，是／否 |
| G | 預計參與方式 | 表單 `attendance`，實體／線上 |
| H | Email | 表單 `email` |
| I | 聯繫電話 | 表單 `phone`，以文字保留前導 0 或國際碼 |
| J | 報名編號 | 網頁產生的 UUID，相同資料重試沿用同一編號 |

## 部署 Apps Script

1. 使用對上述試算表具有編輯權限的 Google 帳號開啟試算表，選擇 **擴充功能 → Apps Script**。
2. 將 [apps-script/Code.gs](apps-script/Code.gs) 的完整內容貼入 `Code.gs`，儲存。程式已填入指定的試算表 ID 與分頁名稱。
3. 在編輯器的函式下拉選單選擇 **setupSheet**，按 **執行**，依 Google 畫面完成授權。此步驟會建立缺少的分頁、設定表頭及外觀。不要直接從編輯器執行 `doPost`；它需要真實表單請求。
4. 檢查「工作坊報名資料」的 A1:J1。若分頁已有資料且表頭不符，程式會停止，不會覆蓋舊資料。請先備份，依上方表頭整理欄位後，再執行 `setupSheet`。
5. 點 **部署 → 新增部署作業**，選擇類型 **網頁應用程式**。
6. **執行身分**選擇自己（擁有試算表編輯權限的部署者）；**誰可以存取**選擇 **任何人**，讓未登入 Google 的報名者也能送出。若機構帳號政策不允許此選項，請洽管理員；僅限機構使用者的部署會要求登入。
7. 完成部署，複製 **網頁應用程式網址**，格式應為 `https://script.google.com/macros/s/部署ID/exec`。請使用 `/exec`，不要使用僅供開發者測試的 `/dev`。

試算表可維持私人權限，不需要改成「知道連結的任何人可編輯」。公開的是報名接收服務；程式不提供讀取名單的介面。網頁應用程式網址屬於公開設定，不是密碼；任何人皆可向公開接收端提交資料，這不是驗證身分或防止惡意投稿的機制。

## 啟用網頁送出

1. 開啟 [index.html](index.html)，搜尋以下設定，將部署的完整 `/exec` 網址貼入引號內：

   ```js
   const APPS_SCRIPT_URL = '';
   ```

2. 儲存並更新 GitHub 上的 `index.html`。空白或格式不符時，網頁仍可閱讀活動資訊，但停用報名預覽與送出，避免未確認名額時受理報名。
3. 可直接使用既有 HTTPS 網站。如要使用 GitHub Pages，在 repository 的 **Settings → Pages** 選擇從 `main` 的根目錄發布。預期路徑是 `https://linmenggann.github.io/TrainingWorkshop/`；請以 GitHub 顯示的實際發布結果為準。
4. 若網頁使用其他網址，修改 `Code.gs` 的 `CONFIG.websiteUrl`，作為結果頁的「返回工作坊網頁」連結。這不影響資料寫入目的地。
5. Apps Script 有修改時，選擇 **部署 → 管理部署作業 → 編輯 → 版本：新增版本 → 部署**。只儲存程式碼不會更新已發布的 `/exec` 行為；更新既有部署可保留原網址。

目前 `index.html` 已填入提供的 Apps Script `/exec` 部署網址。報名預覽及送出按鈕僅在成功讀取名額、尚未達到 4 名上限時啟用；需要將最新版 `Code.gs` 部署為新版本。Google 部署權限、真實名額與試算表寫入仍須依下方流程驗證。本次未送出真實報名資料。

## 報名者操作與結果確認

1. 填寫八項必填資料，按「預覽我的報名資料」。
2. 在預覽視窗確認內容，按「確認送出報名」。網頁以一般 HTML 表單 POST 將資料送至 Apps Script，另開結果分頁；這個流程不依賴 `fetch` 跨來源回應或 `no-cors`。
3. 只有接收端成功寫入並完成 `SpreadsheetApp.flush()` 後，結果頁才顯示「報名已送出」及報名編號。重試已存在的編號會顯示「這筆報名已收到」，不再新增列。原始網頁僅提示查看結果頁，不把分頁開啟當成寫入成功。
4. 驗證失敗、授權失效、表頭不符或其他錯誤會顯示未確認報名的結果；不要把登入頁或空白頁當成成功。保留原頁，確認後以相同資料重試。
5. 同一頁面、相同資料的重試沿用同一編號。更動資料、重新整理、另開頁面或不同裝置會產生新編號，因此**不會依 Email 排除不同報名**。已成功者應避免重新填寫送出。
6. 不確定是否成功時，先請主辦單位依報名編號查看 J 欄。下載的文字檔始終是草稿，不是報名收據。

接收端使用伺服器驗證、寫入鎖、UUID 重試去重，以及公式字元轉義。請不要在 Apps Script 或 repository 放入帳號密碼；報名資料只存到指定試算表。記錄時間使用台北時區，不修改整份試算表的全域時區設定。

## 部署後實際驗證

- 使用無痕視窗開啟 HTTPS 網頁，送出一筆可辨識的測試資料；確認未登入 Google 也能送出。
- 結果頁顯示成功，試算表指定分頁新增一列；核對十欄、電話前導 0、台北時間及報名編號。
- 不修改資料，從原本頁面再送出一次；結果頁應顯示已收到，試算表列數不變。
- 用一筆以 `=` 開頭的測試機構名確認以文字儲存，沒有執行公式。
- 如遭 Google 登入頁攔截，檢查部署存取選項及機構政策；如顯示試算表設定錯誤，檢查部署者權限及 A1:J1。

## 報名現況儀表板 dashboard.html

[dashboard.html](dashboard.html) 使用目前相同的 Apps Script 部署網址，顯示「工作坊報名資料」的真實彙總統計：

- 報名筆數、今日新增（台北時間）、參與機構數、線上參與與現任主持人筆數。
- 12 個職類分布、實體／線上比例、主持人身分與每日／每月報名趨勢。
- 送出日期（含起迄當日）、職類、參與方式、主持人身分篩選；點擊職類長條也可篩選。
- 手動更新、每 60 秒自動更新（分頁在背景時暫停）、統計 CSV 匯出、每日明細表。

### 啟用統計讀取

1. 將 repository **最新版 [apps-script/Code.gs](apps-script/Code.gs) 完整貼回 Google Apps Script**。新版在既有 `doGet(e)` 加入 `action=dashboard` 的統計介面，既有 `doPost` 報名接收流程保留。
2. **部署 → 管理部署作業 → 編輯原部署 → 版本：新增版本 → 部署**，保留目前 `/exec` 網址。只儲存程式碼不會更新已發布的版本。
3. 確認部署執行身分具備試算表讀取權限。沿用「任何人」的部署設定時，儀表板統計可公開讀取，但 Google Sheets 本身仍可維持私人。
4. 將 `dashboard.html` 放在目前網站的根目錄，從報名頁的「報名現況」進入。GitHub Pages 的預期路徑為 `https://linmenggann.github.io/TrainingWorkshop/dashboard.html`，以實際 Pages 發布結果為準。
5. 用無痕視窗開啟儀表板，確認「已連線 · Google Sheets」。對照試算表的報名列數、篩選、日期與最後更新時間；確認網路回應沒有姓名、Email、電話、個別機構名或報名編號。

資料端點為既有 `/exec?action=dashboard`，預設回傳 JSON。網頁加入受限的 `workshopDashboard_...` callback，透過 Google ContentService 的 JSONP 讀取**唯讀彙總資料**，避免跨來源 `fetch` 讀取限制。只有合法 callback 名稱會產生 JavaScript 回應；請勿將此介面改為回傳個人名單。

目前雲端環境連線 Google 受到代理限制（403），因此本次沒有取得真實試算表筆數，也沒有更新 Google 部署。儀表板不內嵌示範數據；啟用新版部署後才會顯示真實統計。若讀取失敗，首次載入顯示「尚未取得資料」；曾成功讀取時保留上次資料，清楚標示更新失敗及最後成功的更新時間。

### 統計口徑

- **報名筆數**計算八項報名欄位至少一項有內容的資料列，不按姓名、Email 或 UUID 去重；空白列不列入。重試去重仍由原本報名接收端負責。
- **機構數**在目前篩選範圍中，以機構名去除首尾空白後的相同文字去重，僅回傳數量，不回傳機構名稱。機構名為空白不計入機構數。
- 未知職類、參與方式或主持人身分列入「未分類」，仍計入總筆數與百分比的分母。
- 支援原表單的 `yyyy/MM/dd HH:mm:ss`、同格式以 `-` 分隔的日期，以及 Sheets 的 Date 儲存格；Date 以台北時間解讀。無法辨識的日期仍列入無日期篩選的總數，顯示品質提醒；不列入趨勢或任何有日期條件的篩選。
- 缺少任一必填欄位的列仍計數，顯示缺欄位筆數。保留測試報名或手動新增的非空白資料列也會計入，請主辦單位自行整理試算表。
- 趨勢在實際有資料的最早至最晚日期間按日顯示；跨度超過 62 天時，改按有報名的月份彙總。圖表最多呈現最後 60 個區間，完整每日統計可展開表格或匯出 CSV。
- 本儀表板提供的是可公開存取的彙總統計，不是有登入驗證的管理後台；不公開個人聯絡資訊，也不提供名單下載。

測試報名接收及統計計算：

```sh
node --test tests/*.test.cjs
```


## 活動限額 4 名與額滿停止受理

本活動**實體及線上合計限額 4 名**。後端設定為 `CONFIG.registrationLimit: 4`；報名頁和儀表板顯示相同上限。

- 報名頁先以 `/exec?action=capacity` 查詢全活動名額，成功確認尚有名額才開啟預覽及送出。查詢不包含任何個人資料。
- 頁面在前景每 30 秒更新名額，返回分頁時也重新確認。點擊送出時若查詢結果已超過 45 秒，會先刷新名額，請確認後再按一次送出。
- 滿 4 名後，自動顯示「額滿」，停用報名欄位、預覽及送出。查詢失敗、舊版部署或回傳上限不符時也暫停受理，不以猜測的名額開放報名。
- **伺服器在同一把 ScriptLock 內檢查已報名數、寫入第 4 筆資料、完成 flush 後才釋放鎖**。即使兩個瀏覽器同時看到最後一席，接收端也只允許一筆新報名取得該席；另一筆會收到「額滿」結果，不新增列。
- 已成功報名的同一 UUID 重試，接收端會先確認原紀錄，回傳已收到，不新增資料也不多占名額。
- 儀表板的額滿與剩餘名額是**全活動狀態**，不受日期、職類、參與方式及主持人身分篩選影響。統計 CSV 也包含上限、全活動已報名數、剩餘名額及額滿狀態。

名額與既有統計口徑一致：八項報名欄位至少一項非空白的列占一名。完全空白列或只有時間／編號的列不占名額；測試報名、部分缺欄位的報名及不同 UUID 的重複填寫仍占名額。請主辦單位自行確認既有資料。如果目前已超過 4 名，程式保留原資料並停止新增，不會刪除既有報名。若主辦單位移除報名紀錄，釋出的名額會在下一次查詢後重新開放。

**部署更新是生效的必要步驟：**完整更新 Google Apps Script 的 `Code.gs`，再到「部署 → 管理部署作業 → 編輯原部署 → 新增版本 → 部署」，保留原 `/exec` 網址。GitHub push 不會更新 Google 部署；只儲存 Apps Script 程式碼也不會啟用新版本。

部署後先以目前真實資料核對名額。若使用獨立測試試算表／測試部署驗證，依序確認第 1～4 筆成功、第 5 筆顯示「額滿」且不新增、同一編號重試不重複，以及篩選後儀表板仍維持全活動額滿狀態；不要向正式試算表新增測試資料來占用活動名額。
